# 요구사항 정의서 — 전자상거래 실시간 상품 추천 MLOps 파이프라인

| 항목 | 내용 |
|---|---|
| 작성 | MLO 1기 5팀 PM 이여찬 |
| 기준일 | 2026-11-20 |

## 1. 구축 목표와 범위

### 1.1 목적

**실시간 행동 반영 추천·구매 전환 예측 서비스와 모델 자동 운영(MLOps) 구축**

- 쇼핑몰 화면의 상품 조회·장바구니 담기 행동을 몇 초 안에 추천에 반영
- 이번 세션의 구매 전환 예측 후 쿠폰 안내
- 상품 추천 모델과 구매 전환 예측 모델의 성능 감시와 자동 재학습
- 평가 통과 시에만 교체
- 문제 발생 시 이전 버전으로 되돌림

### 1.2 범위와 우선순위

| 구분 | 내용 |
|---|---|
| 데이터 | ① 공개 전자상거래 행동 로그(REES46, 2019년 10~12월) 사용<br>② 로그를 시간 순서대로 다시 흘려보내는 재생으로 실제 운영 환경 재현 |
| 시스템 | 재생기 → Kafka → Spark → 온라인 피처 스토어(Redis)·오프라인 피처 스토어(S3의 Delta Lake) → 추천·구매 전환 예측 API → 쇼핑몰 화면 |
| 운영 | ① Airflow 자동 재학습<br>② MLflow 모델 관리<br>③ Prometheus·Grafana 모니터링 |
| 배포 | ① 전체를 AWS에 배포해 서비스<br>② AWS와 같은 구성을 강의장 노트북 클러스터(PC 5대)에 배포해 개발·시험 |

요구사항은 우선순위 세 단계로 구분.

| 우선순위 | 기한 | 뜻 |
|---|---|---|
| P0(필수) | 중간 발표 자료 제출(12-09) 전 | ① 서비스 가능한 수준으로 완료<br>② P0 결과로 중간 발표 진행 |
| P1(고도화) | 최종 발표(01-07) | 중간 발표 뒤 완료 |
| P2(확장) | 없음 | P0·P1이 끝난 뒤에만 시작 |

### 1.3 용어

| 용어 | 뜻 |
|---|---|
| 재생 | ① 과거 로그를 기록된 시각 순서대로 다시 보내 실제 운영을 흉내 내는 것<br>② 배속 변경 가능(10배속이면 하루가 실제 2.4시간) |
| 재생 시각 | ① 재생 중인 기록 속 시각<br>② 집계 구간·유효 기간·재학습 주기는 모두 재생 시각 기준 |
| 세션 | ① 같은 사용자의 행동 간격이 30분을 넘으면 새 세션<br>② 정확히 30분이면 같은 세션<br>③ 월이 바뀌어도 이어짐 |
| 온라인 피처 스토어 / 오프라인 피처 스토어 | 요청 때 바로 읽는 최신 피처 값 저장소(Redis) / 학습·평가용 이력 저장소(S3의 Delta Lake) |
| 관계표(상품 간 유사도 표) | ① "이 상품을 본 사람이 함께 본 상품" 표<br>② 상품 기반 협업 필터링으로 최근 30일 행동에서 생성<br>③ 추천 후보 추출에 사용 |
| 결합 방식(규칙 + 순위 모델) | ① 후보 중 장바구니·최근 관심 상품은 규칙으로 앞에 배치<br>② 남은 자리는 학습된 순위 모델(LightGBM)이 선택 |
| 규칙 순서 | ① 장바구니 → 최근 관심 → 구매 인기 순으로 줄 세우기<br>② 결합 방식이 평가에서 탈락했을 때 쓰는 순서 |
| 대체 추천(폴백) | 저장소 장애나 시간 초과 때 서버 메모리의 인기 상품 목록으로 대신 응답하는 것 |
| 모델 묶음(모델 번들) | 함께 배포·복구해야 하는 것(상품 관계표 버전, 순위 모델, 피처 정의, 전처리, 추천 후보 제외 규칙)을 한 버전으로 묶은 것 |
| 현재 버전 정보 | ① S3에 둔 "지금 서비스할 모델 묶음"을 가리키는 파일<br>② 이 파일 하나만 바꿔 교체·되돌리기 수행 |
| 시점 기준 조회(point-in-time) | ① 과거 어느 시각의 학습 데이터를 만들 때 그 시각 이전에 쓸 수 있었던 값만 쓰는 것<br>② 미래 정보 혼입 방지 |
| 정답 확정 | ① 세션이 끝나 "이 세션에서 샀는가"가 정해진 상태<br>② 확정 전 예측은 평가에서 제외 |
| p95 | ① 측정값을 짧은 순서로 줄 세웠을 때 95% 지점의 값<br>② 요청의 95%가 이 시간 이하라는 뜻 |
| 후보 회수율@100 | 실제로 산 상품이 후보 100개 안에 들어 있던 비율(구매가 있는 요청 기준) |
| Recall@10 / NDCG@10 | ① 추천 10개 안에 산 상품이 들어 있던 비율 / 산 상품이 얼마나 위에 있었는지까지 반영한 순위 점수(0~1)<br>② 요청마다 계산한 값의 평균 |
| 세션 같은 무게의 평균 정밀도 | ① 구매 전환 예측 성능 지표<br>② 예측마다 가중치(1 ÷ 예측이 속한 세션의 예측 수)를 준 평균 정밀도(AP)<br>③ 예측이 많은 세션이 결과를 좌우하지 않게 하는 방식 |
| 소비 밀림(컨슈머 랙) | Kafka에 쌓여 아직 처리되지 않은 메시지 수 |

## 4. 비기능 요구사항(성능·안정성·보안 기준)

**기준값 표기의 뜻**

- "측정 뒤 확정"은 아직 측정 전이라 기준값 미정이라는 뜻
- "가안"은 측정 전에 잡은 목표값, 1차 측정 뒤 재확정
- "논의 목표"는 설계 단계에서 잡은 임시 목표
- 처리량 가안은 원본 로그의 1분 평균 최대 초당 140건 × 재생 10배속 × 여유 1.5배
- P0 판정에 쓰는 기준값은 중간 발표 자료 제출(12-09) 전에 측정값으로 확정
- 데이터 경로의 목표 처리량은 2주 차 말에 측정값으로 확정

### 부록 1. 데이터 파이프라인·피처 스토어

- **FR-DATA-01** 로그 재생과 원본 보관
  - 재생기는 기록 시각 순서·정한 배속으로 Kafka에 전송
  - 재생기의 일시정지·이어서·처음부터 재생
  - 원본을 Parquet로 바꿔 S3의 Delta Lake에 보관(행 수 일치, 다시 변환해도 이벤트 ID 동일)
  - 11월 재생 전 10월 말 상태를 Redis에 적재
    - 대상은 최근 7일 관심·상품별 마지막 행동·최근 30일 구매·열린 세션의 값과 시각
    - 10월 원본에서 계산한 것과 일치
  - 공용 사용자 표본을 해시 규칙으로 추출
    - 두 번 뽑아 같은 결과
    - 작은 표본이 큰 표본에 포함
- **FR-DATA-02** 실시간 피처 계산과 제공
  - 실시간 피처(최근 관심 상품, 상품별 마지막 행동 종류·시각, 장바구니, 최근 30일 구매, 세션 ID)를 같은 규칙으로 Redis와 Delta Lake에 기록
  - 온라인·오프라인 피처 스토어 중 하나가 멈춰도 다른 하나는 계속 기록
  - 세션은 30분 규칙(30분 초과면 새 세션, 정확히 30분이면 같은 세션, 월이 바뀌어도 이어짐)
  - 구매 전환 예측용 최근 행동 5개(같은 상품 반복 포함, 정해 둔 행동 순서와 일치)
  - 순위 모델 특징 18개를 실시간과 학습용으로 같은 정의로 제공(NFR-15)
  - 서빙은 공통 읽기 라이브러리로만 읽음
    - 값·기준 시각·리비전 반환
    - 한 요청의 키를 한 번에 조회
  - Redis 값이 사라지거나 과거 상태로 돌아가면 재적재로 복구(일치율 100%, 이벤트 ID 빠짐·겹침 0)
- **FR-DATA-03** 학습·평가 데이터 생성
  - 추천·구매 전환 예측 모델의 학습 데이터를 시점 기준 조회로 생성(하루 한 번 계산하는 피처는 사용 가능 시각 < 예측 시각)
  - 세션 결과 표와 예측별 정답 표
    - 정답 1/0, 확정·미확정·제외 상태와 제외 이유
    - 구매 전환 예측 명세의 검사 예시 전부 통과
  - 추천 평가용 "요청 뒤 같은 세션에서 산 상품" 표(표본 세션의 구매 상품이 원본과 일치)
  - "이 시각 이전 기록은 모두 처리됨" 시각 공개(밀린 처리가 끝나기 전에는 앞으로 가지 않음)
- **FR-DATA-04** 상품 정보 표와 대체 인기 목록
  - 화면 표시용 상품 정보 표를 PostgreSQL에 제공(카테고리·브랜드·가격·기준 시각)
  - 대체 추천용 인기 목록 일 배치
    - 카테고리별·전체 최근 7일 구매 인기를 생성
    - 대체 추천용 파일로 S3에 게시(시점·버전·상품 순위·체크섬 포함)
    - 생성과 게시는 밀린 처리가 끝난 뒤 재생 시각 기준으로 실행
    - 형식 합의는 PM
- **FR-DATA-05** 서빙 기록 적재와 행동 출처 구분
  - 서빙의 노출·클릭·예측 기록을 Delta Lake에 적재
    - 필수 필드 누락 0
    - 재전송해도 한 번만 적재
    - 재생 실행끼리 섞이지 않음
  - 화면과 부하 시험에서 만든 행동은 출처 표시
    - 학습·평가·드리프트·일 배치 피처에서 제외
    - Redis에는 반영
- **FR-DATA-06** 품질 검사와 데모 점검 자동화
  - 데이터 품질 검사 자동 실행과 실패 알림
  - 데모 대본 자동 실행 점검 스크립트(단계별 통과·실패 출력)
  - 통합 시험마다 점검 스크립트 실행
    - 실제 모델로 확인한 상품·초기 상태·기대 결과를 대본에 고정
    - 구매 확률은 새 행동의 피처로 다시 계산됐는지로 판정
    - 통합 책임은 데이터
- **FR-DATA-07** 드리프트 감지와 추천 성능 지표
  - 입력 분포 변화(드리프트) 감지와 알림
  - 추천 성능 지표(이후 조회 적중률) 집계
    - 분모·인정 범위·중복 처리를 명세에 기록
    - 표본 계산과 일치

### 부록 2. 추천 모델

  - 인기순·협업 필터링 점수순·규칙 순서와 Recall@10·NDCG@10·후보 회수율@100 비교
  - 목표 가안은 Recall@10 0.20·NDCG@10 0.11 이상, 1차 측정 뒤 확정
    - 인기순 기준선 0.18·0.10(10월 구매 상위 10개로 11월 1~2주 구매 세션을 측정한 값)
  - 결합 방식이 규칙 순서보다 낫지 않으면 규칙 순서로 응답
  - 관계표를 바꿀 때 기존 표와 새 표를 같은 요청·정답으로 결합 방식에서 비교
    - 세 지표 중 하나라도 낮으면 기존 표 유지
    - 판정 창과 허용 폭은 측정 뒤 확정
- **FR-REC-03** 모델 등록·자동 재학습·되돌리기
  - 모델 묶음을 MLflow에 등록
  - 모델 묶음 파일은 S3에 보관(체크섬 일치)
  - Airflow 자동 재학습(관계표 생성 → 순위 모델 학습 → 현재 버전과 비교 → 등록·교체 또는 유지와 알림, 추천·구매 전환 예측 모델 공통 파이프라인)
  - 재학습 주기는 설정값(기본 재생 시각 기준 7일, 시연용 짧은 주기로 전환)
  - 이전 준비 완료 묶음으로 되돌리기(실시간 피처 정의가 다른 묶음으로는 차단)

  - 확인 결과 기록
  - 12월 전체를 이미 봤다면 "참고 성능"으로 표시

### 부록 3. 구매 전환 예측

- **FR-PUR-01** 구매 확률 계산과 쿠폰 안내
  - 첫 구매 전의 조회·장바구니 행동마다 이번 세션의 구매 확률 계산
    - 같은 행동 순서에서 학습·서비스 경로의 입력과 확률 일치
    - 초기 서비스 모델은 로지스틱 회귀
  - 예측할 수 없는 경우(구매 완료, 세션 종료, 입력 오류, 시각·버전 불일치, 모델 없음) 확률 빈값·쿠폰 거짓·처리 상태와 사유 반환
  - 처리 상태(정상·예측 대상 아님·입력 오류·모델 사용 불가)마다 시험
  - 확률 10% 이상 30% 미만이면 세션당 한 번 쿠폰 안내
    - 경계값 9.9%·10%·29.9%·30%와 같은 세션 두 번째 진입에서 시험
    - 규칙은 구매 전환 예측 담당
    - 표시는 서비스 담당
- **FR-PUR-02** 정답 규칙과 성능 평가
  - 정답·제외 규칙을 명세와 검사 예시로 제공
    - 다음 세션의 구매는 붙이지 않음
    - 첫 구매와 같은 시각의 예측 제외
    - 끝나지 않은 세션과 구간 경계 세션은 미확정
    - 늦은 기록이 있는 세션은 제외(제외 이유 기록)
  - 확정된 정답으로 세션 같은 무게의 평균 정밀도와 확률 보정 집계(표본 계산과 일치)
  - 장바구니 규칙·비교용 LightGBM과 같은 예측 행·정답으로 평균 정밀도·확률 보정·상위 구간 정밀도 비교
  - 목표 가안은 AP 0.20 이상(예측 행 기준)
    - 10월 27~31일 사용자 1% 개발 평가에서 장바구니 담기 여부만 보는 단순 규칙 0.148
    - 같은 개발 평가에서 서비스용 로지스틱 회귀 0.204
  - 세션 같은 무게 기준은 1차 측정 뒤 확정
- **FR-PUR-03** 모델 등록과 자동 재학습
  - 모델 묶음(피처 목록·전처리·확률 보정·쿠폰 구간 경계)을 MLflow에 등록
  - 모델 묶음 파일은 S3에 보관(체크섬 일치)
  - 추천과 같은 공통 재학습 파이프라인으로 자동 재학습

### 부록 4. 서비스(화면·API)

- **FR-SVC-01** 쇼핑몰 화면과 비로그인 응답
  - 상품 목록·상세·장바구니와 추천 목록 화면
  - 비로그인 응답(로그인 없이, 또는 DB를 읽지 못할 때 사용자 계정 정보 없이 응답하는 방식, PostgreSQL이 멈춰도 목록·상세·대체 추천 카드 표시)
  - 결제 없는 구매 버튼
    - 구매한 상품은 다음 추천 목록에서 제외
    - 화면에서 만든 구매는 학습·평가에 미사용
- **FR-SVC-02** 화면 행동 전송과 추천 갱신
  - 조회·장바구니·구매 행동을 Kafka로 전송
    - 실패하면 화면이 다시 전송
    - 다시 보내도 한 번만 반영
  - 보고 있는 화면의 추천은 바꾸지 않음
  - 추천 영역이 있는 다음 화면을 열 때 마지막 행동의 반영 여부를 확인하고 추천을 요청(뒤로 가기로 복원될 때 포함)
  - 반영이 늦으면 대기 한도까지 기다린 뒤 기존 추천 표시(한도는 측정 뒤 확정)
- **FR-SVC-03** 추천·구매 전환 예측 API
  - 추천·구매 전환 예측은 추천 API(FastAPI)가 담당
  - Django가 내부 토큰으로 호출
    - 토큰 없는 호출 거부
    - 추천 API는 클러스터 안에만 공개
  - 요청 시작 때 모델 묶음 버전 고정
  - 응답 완료까지 같은 버전 유지
  - 구매 확률 엔드포인트와 쿠폰 안내 표시
  - 관계표를 버전별로 PostgreSQL에 적재
    - 행 수·체크섬·표본 조회 검증을 통과한 버전만 사용
    - 검증 실패 시 교체 차단
    - 검증 기준은 추천 담당
- **FR-SVC-04** 노출·클릭·예측 기록
  - 노출·클릭·예측 기록을 Kafka로 전송
    - 카드 5장 반환·2장 노출·1장 클릭이면 예측 1·노출 2·클릭 1건
    - 클릭은 실제 노출에 연결
  - 조회·장바구니 행동마다 피처 반영을 확인한 뒤 구매 전환 예측을 한 건씩 기록
    - 빠르게 이어진 두 행동에 두 건
    - 같은 행동 재전송은 같은 예측 ID로 한 건
- **FR-SVC-05** 저장소 장애 대응
  - Redis·PostgreSQL을 읽을 수 없으면 메모리의 인기 목록으로 대체 추천(대체 상태와 사용 버전 기록)
  - PostgreSQL은 쓰기용 접속 주소로 연결
  - PostgreSQL 재시작 뒤 자동 재연결
- **FR-SVC-07** 과부하 대응과 부하 시험
  - 과부하 때 정한 구간까지는 대체 추천
  - 정한 구간을 넘는 과부하는 빠른 거절(파드마다 동시 처리 상한과 시간 초과)
  - 화면 요청 부하 시험 시나리오(추천·구매 확률·반영 확인·행동 전송·노출·클릭 로그 포함)와 결과 보고

  - 작업 공통 템플릿(표본 작업 등록·실행)

    - Feast가 함께 돌지 않으면 직접 구현

  - Kafka·Redis·PostgreSQL을 영속 볼륨에 배치
  - 삭제 정책은 보존(파드·배포 설정을 다시 만들어도 데이터 유지)

    - CloudNativePG 사용
    - AWS와 노트북 클러스터 모두 서로 다른 서버에 배치
    - 전환 시간 측정

  - 복원 시험 1회 이상

  - Prometheus로 지표 수집

  - 1주 차에 1차 견적
  - 2주 차 이후 실측으로 수정(전체 AWS안과 혼합 배치안, 전체 사용자 재생 기준)
