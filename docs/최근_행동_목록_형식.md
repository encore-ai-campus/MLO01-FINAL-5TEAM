# 구매 전환 예측용 최근 행동 목록 형식

| 항목 | 내용 |
|---|---|
| 만드는 쪽 | 데이터(실시간: Redis 반영 작업, 학습: Delta 정제 표에서 계산) |
| 쓰는 쪽 | 구매 전환 예측(입력 6개 계산 함수, 학습과 실서비스 공용) |
| Redis 키 | `feat:session:{세션 ID}:actions`(리스트) |

## 1. 무엇을 담나

한 세션에서 판정을 통과한 **조회·장바구니 담기 최근 5개**를 시간 순서대로 담는다. 같은 상품을 다시 본 것도 그대로 남긴다.

- 예: A 조회 → A 조회 → B 장바구니면 목록은 세 칸 `[A 조회, A 조회, B 장바구니]`다.
- "최근 본 상품 20개" 목록은 같은 상품을 다시 보면 맨 앞으로 옮기고 중복을 없앤다. 그래서 "같은 상품을 연달아 본 횟수" 같은 순서 정보를 계산할 수 없어 이 목록을 따로 둔다.

## 2. 한 칸의 필드

| 필드 | 타입 | 뜻 |
|---|---|---|
| `seq` | 정수 | 세션 안 순번. 판정을 통과한 조회·장바구니마다 1부터 하나씩 늘림 |
| `sequence` | 정수 | 원래 행동의 순서 번호(토픽 메시지 형식). 재생은 원본 행 순번, 화면은 브라우저가 매긴 번호 |
| `event_id` | 문자열 | 원래 행동의 이벤트 ID(추적용) |
| `product_id` | 문자열 | 상품 ID |
| `event_type` | 문자열 | `view` 또는 `cart` |
| `event_time_utc` | 문자열 | 행동 시각. 토픽 메시지 형식과 같은 UTC, ISO 8601, 밀리초까지 |

- ID는 Kafka 메시지·Delta 표와 같이 문자열로 둔다.
- 구매 전환 예측 설계의 "순서 번호"는 `sequence`다. `seq`는 목록 안 순서를 바로 읽기 위한 세션 안 번호다.
- 같은 시각의 행동은 `seq`로 순서를 가린다.

## 3. 목록 규칙

| 규칙 | 내용 |
|---|---|
| 순서 | 오래된 것 → 최근 것. 마지막 칸이 가장 최근 행동 |
| 개수 | 최대 5개. 6번째가 들어오면 가장 오래된 칸을 뺀다 |
| 5개보다 적을 때 | 있는 만큼만 담는다. 빈칸을 채우지 않는다 |
| 넣는 행동 | 판정을 통과한 `view`, `cart`만. 늦음·중복 판정, 장바구니 빼기, 구매는 넣지 않는다 |
| 순서를 정하는 기준 | 판정 작업이 통과시킨 순서(정제 토픽 순서). 학습도 정제 표의 판정 결과와 순서를 그대로 쓴다 |
| 범위 | 판정 작업이 붙인 세션 ID 하나. 세션 ID가 바뀌면 빈 목록에서 다시 시작한다. 월이 바뀌어도 세션이 이어지면 목록도 이어진다 |
| 첫 구매 뒤 | 목록은 계속 갱신하지만, 그 세션에서 새 구매 전환 예측은 만들지 않는다 |
| 기준 행동 | 예측 요청의 목록은 기준 행동까지 넣은 것이다. 마지막 칸이 늘 기준 행동이다 |
| 재생 예측 표본 | 표본으로 뽑히지 않은 세션도 목록을 똑같이 유지한다. 표본 비율을 바꿔도 목록 규칙은 그대로다 |

세션 경계는 판정 작업이 정한다. 같은 출처·재생 실행·메시지 키에서 직전 통과 행동과 30분을 넘게 떨어지면 새 세션이고, 늦음·중복 판정을 받은 행동은 세션을 열거나 늘리지 않는다. 이 목록은 그 세션 ID를 그대로 따른다.

## 4. 어디에 두고 누가 쓰나

| 쓰임 | 위치 | 비고 |
|---|---|---|
| 실서비스 | Redis 리스트 `feat:session:{세션 ID}:actions` | 한 칸은 위 필드를 담은 JSON 문자열 |
| 학습·평가 | Delta 정제 표에서 같은 규칙으로 계산 | 예측 기준 행동 시점의 목록을 다시 만든다 |
| 계산 규칙 | 공용 피처 패키지의 함수 하나 | 실시간 쓰기와 학습용 계산이 같은 함수를 쓴다 |

실시간에서는 Redis 반영 작업이 이 목록을 읽고 쓴다. 한 배치는 아래 순서로 처리한다.

1. 대상 세션의 현재 목록을 읽는다.
2. 행동마다 그 행동까지 넣은 목록을 만들고, 예측 대상이면 이 목록으로 입력 6개를 계산해 예측 요청을 쓴다. 같은 배치에 한 세션의 행동이 여럿이면 행동 하나씩 반영한 중간 목록과 중간 구매 여부로 판단한다.
3. 요청 쓰기 확인을 받은 뒤 목록을 Redis에 반영한다. 세션 피처, 피처 리비전, 처리 위치와 같은 쓰기 스크립트에서 함께 바꾼다.

- 구매 전환 예측 API는 요청에 담긴 입력만 쓰고 이 목록을 읽지 않는다.
- 입력 6개 계산 함수(구매 전환 예측 담당)는 이 목록만 입력으로 받는다. 학습과 실서비스가 같은 함수를 쓴다.
- 이미 반영한 행동(처리 위치로 판단)과 정제 토픽의 중복 사본은 목록을 만들기 전에 거른다. 거르는 규칙은 데이터 파이프라인 설계서를 따른다.
- 만료와 삭제는 세션 키와 함께 한다. 세션 키의 만료를 늘리면 이 목록도 늘리고, 세션이 끝나 지울 때 함께 지운다.
- Redis를 다시 채울 때는 Delta 정제 표에서 같은 함수로 목록을 다시 만든다.

## 5. 예시

B 조회 뒤 다른 상품 D를 장바구니에 담은 세션. 기준 행동은 D 장바구니다.

```json
[
  {"seq": 1, "sequence": 1052, "event_id": "2019-Oct.csv.gz:1052", "product_id": "B", "event_type": "view", "event_time_utc": "2019-10-01T10:00:00.000Z"},
  {"seq": 2, "sequence": 1187, "event_id": "2019-Oct.csv.gz:1187", "product_id": "D", "event_type": "cart", "event_time_utc": "2019-10-01T10:01:00.000Z"}
]
```

구매 전환 예측 함수가 이 목록에서 내는 값: 행동 수 2, 연속 조회 0, 상품 전환 비율 1.0, 이전 상품 복귀 0, 행동 관계 `view_cart_other`, 상품 패턴 `AB`.
